# 职镜 × ResumeSkills 借鉴评审清单

> 来源对照：ResumeSkills（22 个 AI agent skill 集合）→ 职镜 JobMirror
> 共 8 个借鉴点，按「对用户价值的直接提升程度」排序
> 勾选 = 确认纳入，未勾选 = 暂不处理

---

## 1. ATS 格式检查 → 补入 resumeSuggestions 输出

**现状**：职镜的简历修改建议不含 ATS 兼容性检查，用户可能按建议改完后仍被机筛淘汰。
**借鉴**：`resume-ats-optimizer` 的 ATS 检查清单（文件格式/字体/排版/Section 标题/联系方式位置）。

具体纳入内容：

- [x] a. **文件格式警示** — 生成报告时检查用户上传的简历格式是否为 `.docx`/`.pdf`，若非标准格式给出警告
- [ ] b. **文件命名规范** — 建议 `姓名_目标岗位_简历.pdf` 格式
- [x] c. **排版红线检查** — 在 `resumeSuggestions` 中增加 ATS 检查维度：
  - [x] 是否使用了表格/分栏/文本框（ATS 解析失败的主因）
  - [x] 联系方式是否在页眉页脚（应移到正文）
  - [x] 是否有图片/图表/特殊字符
- [x] d. **Section 标题标准化** — 检查用户简历板块标题是否用标准命名（「工作经历」而非「我的足迹」）
- [x] e. **关键词密度规则** — 在 JD 对标建议中加入：核心关键词建议出现 2-4 次，重要关键词 1-2 次

**改动范围**：`skill/SKILL.md` 工作流 2 步骤 6（resumeSuggestions 生成逻辑），从前端侧需要能读取到简历原文。

## 2. 关键词三分类法 → 强化 JD 解析与技能差距输出

**现状**：职镜把 JD 技能统一标为 `requiredSkills[]`，不区分类型。
**借鉴**：`resume-ats-optimizer` 的关键词三分类（Hard Skills / Soft Skills / Industry Terms）。

- [x] a. **JD 解析时分类** — 提取 `requiredSkills` 时新增 `category` 字段：
  - `hard`：编程语言/工具/证书/方法论（Python, AWS, PMP, Agile）
  - `soft`：沟通/领导力/分析思维/项目管理
  - `industry`：行业术语（B2B, SaaS, ARR, MAU, GMV）
- [x] b. **技能差距按类别汇总** — 报告输出时分组展示：「你缺 2 项硬技能、1 项行业术语」比「你缺 3 项技能」更有指导性
- [x] c. **简历建议按类别优先排序** — hard 技能缺失优先提醒，industry 术语次之，soft 技能最后

**改动范围**：`docs/data-model.md`（JD json schema 加字段）、`skill/SKILL.md` 工作流 2 步骤 3-4、前端 `GapBreakdown.vue` 按类别分组渲染。

## 3. 子弹点改写方法论 → 让简历建议更可执行

**现状**：职镜的 `resumeSuggestions` 给出 issue → suggestion，但建议偏笼统（"补充量化数据"）。
**借鉴**：`resume-bullet-writer` 的弱→强子弹改写公式和 Before/After 对比格式。

- [x] a. **改写公式模板** — 生成建议时遵守统一结构：
  `[动词] [做了什么] [通过什么方式] [产生了什么可量化结果]`
- [x] b. **量化注入规则** — 即使原始简历无数字，给出合理估算范围（如"参与用户增长"→"通过 A/B 测试推动约 15% 的月活提升"），标注为估计值
- [x] c. **Before/After 对比** — `suggestion` 字段升级为原文 → 改写后 的对比格式，而非仅描述性建议

**改动范围**：`skill/SKILL.md` 工作流 2 步骤 6（suggestion 生成规范）、前端 `Suggestions.vue` 增加对比视图。

## 4. STAR 故事生成 → 补强 interviewPrep

**现状**：职镜的 `interviewPrep` 输出为 topic + importance + prepPoints[]，内容是 checklist 式的准备动作列表。
**借鉴**：`interview-prep-generator` 的 STAR 叙事生成——从简历中每条经历提取结构化故事。

- [x] a. **STAR 化 interviewPrep** — 对每条经历生成一个完整的 STAR 叙事块：
  - **S**ituation：项目/任务的背景和挑战
  - **T**ask：你被分配的具体目标
  - **A**ction：你采取了什么行动
  - **R**esult：可量化的结果
- [x] b. **针对技能差距的「包装话术」** — 对 partial 技能，生成一份「如何把现有经验对应到 JD 要求」的 STAR 回答框架（可以借鉴，但是具体页面的实现交互方式需要进一步确认）
- [x] c. **高频面试题预测** — 基于 JD 职责列表 + 用户技能差距，预测 3-5 个高概率被问到的行为面试题（可以借鉴，但是具体页面的实现交互方式需要进一步确认）

**改动范围**：`skill/SKILL.md` 工作流 2 步骤 7（interviewPrep 生成逻辑）、前端 `ReportDetail.vue` 的 interview 展示区。

## 5. 薪资谈判框架 → 新增辅助 skill 或扩展工作流（可以考虑纳入，作为独立模块，作为知识查询的方式进行展示，独立页面，不做交互，仅作为页面静态知识库相关展示）

**现状**：职镜明确禁止给出具体薪资建议，但「谈判策略」≠「薪资估值」。
**借鉴**：`salary-negotiation-prep` 的谈判框架，不涉及具体数字建议。

- [ ] a. **薪资构成认知框架** — 在报告或独立工作流中输出薪资包拆解清单（底薪/绩效奖金/签约奖金/股权/福利），帮用户理解哪些是谈判筹码
- [ ] b. **谈判话术模板** — 提供中性的还价措辞模板（"感谢 offer，我对 XX 方面有疑问，能否..."），不绑定具体金额
- [ ] c. **常见谈判陷阱提醒** — "HR 说这是最终报价""限时 24 小时决定"等常见施压策略及应对建议
- [ ] d. **决定是否纳入**：此点偏离核心"技能对标"定位较多，属于扩展功能
  - [ ] 纳入（作为报告的附加模块或独立工作流）
  - [x] 暂不纳入（保持聚焦）

**改动范围**：如果纳入，新增 `skill/SKILL.md` 工作流 7（薪资谈判框架）、`docs/data-model.md` 可能不需要改动（纯分析输出）。

## 6. Offer 对比维度扩展 → 强化工作流 6

**现状**：职镜的工作流 6「对比岗位」目前只基于匹配度 + 技能差距做单维对比。
**借鉴**：`offer-comparison-analyzer` 的多维对比矩阵。

- [x] a. **新增对比维度**：（可以借鉴，但是具体页面的实现交互方式需要进一步确认）
  - [x] **成长空间**：岗位的晋升路径/学习机会（从 JD 职责范围 + 团队规模推断）
  - [x] **行业匹配**：目标行业与用户当前行业的距离（同行业/相邻/跨界）
  - [x] **技能天花板**：该岗位对用户的核心技能能提升到什么程度
  - [x] **简历修改工作量**：对比两个岗位需要的简历调整量（需要改多少处）
- [x] b. **决策建议矩阵** — 综合匹配度 + 成长空间 + 行业匹配，给出加权推荐，而非仅匹配度排序

**改动范围**：`skill/SKILL.md` 工作流 6 对比维度、前端 `JDDetail.vue` 或新增对比页面。

## 7. 触发词路由优先级 → 消除工作流匹配歧义

**现状**：职镜的 7 个工作流各自有触发词列表，但存在重叠（如"分析"和"对标"同时命中工作流 2 和 6），可能出现误匹配。
**借鉴**：ResumeSkills 的 `config.json` 中每个 skill 有 `triggers` 数组 + 插件层面的路由优先级机制。

- [ ] a. **工作流路由规则表** — 在 SKILL.md 新增路由优先级表：

| 优先级 | 工作流 | 判断条件 |
|-------|--------|---------|
| 0 | 工作流 0 (收件箱) | inbox/resume.txt 存在且未 .processed |
| 1 | 工作流 4 (修改技能) | 消息含「提升/新增/删除」+ 技能名 |
| 2 | 工作流 6 (对比) | 消息含「对比/比较/选哪个」 |
| 3 | 工作流 2 (分析) | 消息含 JD 原文 或「分析/对标/匹配」 |
| 4 | 工作流 5 (查看报告) | 消息含「报告/查看报告」 |
| 5 | 工作流 3 (查看档案) | 消息含「档案/技能清单/我的资料」 |
| 6 | 工作流 1 (导入简历) | 消息含文件路径 |

- [x] b. **歧义处理规则** — 优先级高的工作流不满足前置条件（如无 profile）时，自动降级到次优先工作流

**改动范围**：`skill/SKILL.md` 新增「工作流路由」章节。

## 8. 边界情况文档化 → 新增系统化处理指南

**现状**：职镜的 SKILL.md 隐式处理了部分边界情况（如年限推算中的应届生处理），但散落在各章节。
**借鉴**：ResumeSkills 的 `Edge Cases & Special Situations` 章节，集中列出特殊场景的处理策略。

- [x] a. **新增「边界情况处理」章节**，覆盖以下场景：

  - [x] **应届生 / 0 年经验**：教育权重临时提高到 0.4，技能匹配全靠课程/项目/实习
  - [x] **职业转行者**：放宽技能语义匹配（允许"可迁移技能"跨类别映射），降低年限权重
  - [x] **高管 / 10 年+经验**：ATS 检查仍适用，JD 解析时侧重战略维度词汇（P&L/团队规模/董事会经验）
  - [x] **就业空白期**：不扣分不提醒（避免制造焦虑），关注最近一份经历的相关性
  - [x] **多重 JD 版本**：同一岗位保存多版 JD 时，slug 追加 v2/v3 避免覆盖
  - [x] **超大简历文件**：提醒用户截取核心经历，而非全文解析
  - [x] **纯英文简历**：技能对标时中英文自动映射（Python↔Python，数据分析↔Data Analysis）

- [x] b. **在评分公式中体现边界权重调整** — 如检测到应届生时动态调整权重：`overallScore = skillMatch × 0.3 + educationMatch × 0.5 + experienceMatch × 0.2`

**改动范围**：`skill/SKILL.md` 新增章节、评分标准章节补充动态权重说明。

## 决策汇总

| # | 借鉴点 | 价值 | 改动量 | 决定 |
|---|--------|------|--------|------|
| 1 | ATS 格式检查 | 高 — 直接提升报告实用性 | 中 | ☐ 纳入 / ☐ 暂缓 / ☐ 不做 |
| 2 | 关键词三分类 | 高 — 让差距分析更精准 | 中 | ☐ 纳入 / ☐ 暂缓 / ☐ 不做 |
| 3 | 子弹点改写方法论 | 高 — 建议从"该改"变成"怎么改" | 小 | ☐ 纳入 / ☐ 暂缓 / ☐ 不做 |
| 4 | STAR 故事生成 | 中 — 面试准备更有深度 | 中 | ☐ 纳入 / ☐ 暂缓 / ☐ 不做 |
| 5 | 薪资谈判框架 | 中 — 偏离核心定位 | 大（新增工作流） | ☐ 纳入 / ☐ 暂缓 / ☐ 不做 |
| 6 | Offer 对比维度 | 低 — 使用频率低 | 小 | ☐ 纳入 / ☐ 暂缓 / ☐ 不做 |
| 7 | 触发词路由优先级 | 中 — 减少误匹配 | 极小 | ☐ 纳入 / ☐ 暂缓 / ☐ 不做 |
| 8 | 边界情况文档化 | 中 — 提升鲁棒性 | 小 | ☐ 纳入 / ☐ 暂缓 / ☐ 不做 |

---

> 建议策略：优先做改动量小 + 价值高的（3, 7, 8）→ 再做中改动量的（1, 2, 4）→ 最后评估是否扩展新功能（5, 6）。
